## Локальный просмотр

Из корня frontend:

```powershell
python -m http.server 8780 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:8780/admin/`. Этот сервер нужен для frontend/CMS; он не принимает заявки. Существующий FastAPI остаётся отдельным сервисом. `/api/lead`, его контакты, подтверждения доставки и антидубли не менялись.

## Работа в кабинете

1. «Мои объекты» → «Добавить объект». Заполнить название и характеристики.
2. Загрузить до 12 фото; до отправки они преобразуются в WebP, до 1920 px и 1,5 МБ на фото, без EXIF/GPS. Оригиналы не загружаются. HEIC работает только если браузер умеет его декодировать; иначе нужен JPEG.
3. Выбрать главное фото и порядок кнопками. «Сохранить черновик» сохраняет объект закрытым.
4. «Предпросмотр» открывает действующий шаблон `property.html`. Черновик передаётся только в память новой вкладки через проверенный same-origin postMessage; фото — временные blob URL. Черновиков в публичном JSON/репозитории нет.
5. Подтвердить право публикации → «Опубликовать». Изменения цены/фото опубликованного объекта сохраняются кнопкой «Сохранить изменения».
6. Статус «Продано» автоматически снимает объект с публикации. «Снять с публикации» сохраняет черновик. Удаление требует отдельного подтверждения.

«Фото каталога» — самостоятельные обложки шести категорий. «Новостройки» — квартиры с `market=newbuild`, а не отдельный несовместимый тип.

- Пока у категории ещё никогда не было настоящего фото, сохраняется текущая утверждённая иллюстрация сайта с явной подписью. После первой реальной публикации или ручной обложки возврата к ней нет.
- Автоматический выбор: главное фото первого по `published_at`, затем ID опубликованного объекта категории. Выбор не случайный.
- Ручной выбор фото из опубликованного объекта и кадрирование; или отдельная загрузка с подтверждением права публикации.
- Ручная обложка не заменяется при добавлении объектов. Если объект-источник скрыт/удалён, выбирается следующая разрешённая фотография или пустое состояние. Отдельная загруженная обложка остаётся независимой.
- При автоматическом выборе — кадр по центру. Для своего кадрирования нужно выбрать конкретную фотографию или загрузить отдельную.

## Публичный сайт и доступ

`cms-public.js` читает `public_catalog()` через публичный ключ, `cache: no-store`, без клиентских форм и Auth SDK. Он сохраняет формат текущего каталога: `schemaVersion`, `properties`, `reviews`; страницы и фильтры остаются прежними.

При подключённой CMS публичный JSON не используется как запасная устаревшая копия. При сбое — честное сообщение о недоступности. Снятый объект не появится снова из кешированного JSON. Каталог/страница объекта перечитываются при возвращении во вкладку и раз в 45 секунд; новая загрузка всегда читает свежие данные. Главная обновляет только обложки, не трогая заполненную форму заявки.

Прямой доступ anon к таблицам и приватному Storage запрещён. Редактирование — только транзакционными RPC с проверкой allowlist. `revision` защищает от перезаписи изменений из другой вкладки. Неавторизованный пользователь не может записать себя в allowlist.

Посетители получают фото через Edge Function: каждый запрос повторно проверяет, опубликован ли объект или разрешена ли отдельная обложка. `Cache-Control: no-store`, без публичных signed URL, поэтому снятие объекта закрывает новые запросы фото. Уже скачанные посетителем изображения отозвать технически невозможно.

Администратор видит закрытые фото через короткие подписанные ссылки в своём сеансе. Это не публичные ссылки. Выгрузка приватных фото требует Auth и RLS.

## Аккаунт и восстановление

Пользователь задаёт пароль сам. Закрытая регистрация не мешает существующему разрешённому аккаунту входить по паролю. Для замены временного аккаунта на аккаунт Ильсияр: создать нового пользователя в Auth, добавить его UUID в `cms_admins`, проверить вход, затем отозвать старый UUID. Каталог не привязан к адресу почты.

Кнопка восстановления подключена к Supabase Auth. У стандартной почты Supabase есть ограничение: письма направляются только участникам команды проекта; для других адресов нужен отдельно настроенный SMTP. В этой задаче новый почтовый сервис и платный SMTP не подключались. Если письмо не приходит, владелец проекта восстанавливает доступ через Supabase. Не обещать доставку recovery-писем без проверки SMTP.

## Free: ограничения и резервная копия

На дату проверки 01.11.2026: 500 МБ Database, 1 ГБ Storage, 5 ГБ egress и 5 ГБ cached egress; 2 активных Free-проекта; проект может приостанавливаться после недели неактивности. Edge Functions также расходуют бесплатную квоту (смотреть текущий Usage). Платный тариф не подключён. Постоянная доступность Free не гарантирована; восстановление приостановленного проекта — вручную в Dashboard, без искусственного прогрева.

В «Резервной копии» скачивается ZIP с `catalog-backup.json` и всеми используемыми фото объектов/отдельных обложек, включая черновики. В архиве нет паролей, сессий или ключей. Крупная выгрузка делится на части примерно по 30 МБ; сохранить все части. Хранить архив приватно, ещё одну копию — на другом устройстве. На Free автоматического backup здесь нет. Кнопка «Очистить незавершённые загрузки» удаляет после подтверждения только неиспользуемые фото старше суток; действующие фото дополнительно защищены Storage RLS.

Восстановление — техническая операция владельца проекта: сначала приватная загрузка файлов в сохранённые пути, затем черновики через `cms_save_property` с `expected_revision=0`, фотографии и обложки, после проверки — повторная публикация только нужных объектов. Не импортировать архив в публичный репозиторий. Перед восстановлением сохранить текущую копию; не перезаписывать существующие объекты без проверки `revision`. Удалённые неиспользуемые загрузки не входят в архив.

Supabase-проект расположен в Лондоне. В Auth обрабатываются почта административного аккаунта, данные сеанса и технические журналы. Публичные обращения к API/медиа также передают сервису IP и технические данные соединения. **Это не подтверждение соблюдения требований РФ.** Применимость 152-ФЗ, локализации, оснований и уведомлений о трансграничной передаче нужно отдельно оценить до запуска с реальными данными. Клиентские заявки, телефоны клиентов, документы и сведения о сделках в CMS не загружать. Форма заявок не переносилась.

В объявлениях публиковать только разрешённые данные и фото, без людей, документов, ФИО собственников и иных персональных сведений. Согласие на обычную публикацию фото не заменяет правовую оценку размещения данных за рубежом.

## Проверка и публикация

- `supabase/tests/catalog_security.sql` проверяет настоящие роли Postgres, RPC, RLS, черновики, Storage, публикацию, отсутствие фото и отзыв прав после снятия. Все синтетические fixtures откатываются через ROLLBACK.
- UI-сценарий проходит на изолированном transport mock вне исходников сайта. Демообъявления в `catalog.json` не добавляются.
- Итоговый проход: 30 проверок UI (включая 768/390/360 px), 37 проверок неизменённой формы с перехватом API, без реальных заявок. Проверки ролей и публикации выполнены отдельно в настоящем Postgres и завершены ROLLBACK.
- Настоящий вход после восстановления пароля и полный цикл в отдельном Supabase-проекте проверены: приватная загрузка двух фото, выбор главного, сохранение черновика, публикация, изменение цены и статуса, ручная обложка с кадрированием, отдельная загрузка обложки, ZIP с данными и тремя фото, снятие и удаление. Публичный API и реальные локальные страницы подтверждают результат. Снятие закрывает доступ к фото; отдельная обложка остаётся независимой.
- После настоящего теста удалены синтетический объект и все три файла, исходные обложки восстановлены. Проверка базы: 0 объектов, 0 фото, 0 файлов в bucket. Восстановление доступа отдельно проверено на трёх имитированных сценариях, ошибки входа — на четырёх; реальные письма в этих автоматизированных проверках не отправлялись.
- Для локального восстановления письмо нужно открывать на том же компьютере: разрешённый redirect ведёт на `127.0.0.1`. На телефоне локальный адрес не указывает на компьютер. После выпуска используется публичный `/admin/`. Недействительная ссылка показывает явную ошибку и предлагает запросить новую.
- Production пока не обновлять. После утверждения — обычный commit/push существующей ветки в main без force push и проверка `/admin/`, каталога и страницы объекта. DNS, CNAME, Pages, Render и бот не меняются.
